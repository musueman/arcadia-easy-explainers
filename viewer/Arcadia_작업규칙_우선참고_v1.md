# Arcadia 작업규칙 우선참고 v1

이 문서는 Arcadia 정본 확장 작업에서 매 회차 먼저 확인할 작업 규칙을 모은다. 정본 본문에는 결론만 남기고, 작업 과정과 선택지는 이 문서나 소플랜에만 둔다.

## 우선순위

| 순위 | 기준 | 적용 |
|---:|---|---|
| 1 | `Arcadia_마스터_객관정보_정본_v1.md` | 실제 물리·자연·장기 구조의 검산 기준 |
| 2 | `Arcadia_기준시대_5083_자연오버레이_v1.md` | 5083년에 적용되는 자연 상태 선택값 |
| 3 | `Arcadia_기준시대_5083_객관정보_v1.md` | 5083년 사람들이 알고, 말하고, 제도화하는 기준시대 객관정보 마스터 |
| 4 | `Arcadia_기준시대_5083_사회문화_핵심정보_v1.md` | 물리 객관정보에는 넣지 않지만 기준시대 세계를 성립시키는 권역·국가·종족·달력·법·신앙·장소·전승 핵심정보 |
| 5 | 회차 소플랜과 허브 | 현재 안건, 다음 실행 대상, 검증 기준 |
| 6 | 원천 문서와 초안 | 정본에 넣기 전 대조 자료 |

## 분리 규칙

| 항목 | 규칙 |
|---|---|
| 객관정보 | 시대와 인물의 인식 밖에 있는 실제 세계 구조만 둔다. |
| 기준시대 객관정보 | 객관정보를 기준시대의 관측 가능성, 오해, 명칭, 제도, 직능 지식으로 변환한다. |
| 기준시대 사회문화 핵심정보 | 물리·자연 객관정보는 아니지만 기준시대 세계를 굴리는 권역, 국가, 종족 분류, 달력, 법, 신앙, 장소, 전승 정보는 별도 핵심정보군으로 둔다. |
| 특정 이야기 정보 | 기준시대 객관정보를 바탕으로 따로 파생한다. 기준시대 객관정보가 특정 이야기의 사건표가 되지 않게 한다. |
| 역사·사건 | 현재 상태에 필요한 요약만 기준시대 객관정보에 두고, 상세 전개는 별도 역사·사건 문서로 넘긴다. |
| 인물관계 | 마지막 단계까지 정리하지 않는다. |
| 챗봇 전용 반영본 | 사용자가 명시적으로 요청하기 전까지 제작·정리하지 않는다. |

## 응답 모드 우선순위

| 응답 모드 | 우선 참조 | 객관정보 사용 | 금지선 |
|---|---|---|---|
| 정본 검산·편집 | 마스터 객관정보, 자연 오버레이, 기준시대 객관정보 순서 | 수치·ID·물리 조건을 직접 확인한다. | 검산 우선순위를 인월드 지식 우선순위로 착각하지 않는다. |
| 인월드 인물 응답 | 기준시대 객관정보, 해당 지역·장소·직능 문서, 사건 문서 순서 | 객관정보는 조용한 검산 기준으로만 사용하고, 응답 표면 필드로 접근권을 먼저 낮춘다. | `OBJ-*`, `VIR-*`, 물리 수치, 숨은 원인을 인물 발화에 노출하지 않는다. |
| 설정 설명 응답 | 객관정보와 기준시대 객관정보를 함께 보되 층위를 분리한다. | 객관 사실과 기준시대 인식을 나누어 설명한다. | 설정 설명을 인물 발화나 사회 상식으로 섞지 않는다. |
| 챗봇 전용 반영본 | 사용자가 요청한 뒤 별도 생성한다. | 확정 정본을 요약·가공하되 새 사실을 만들지 않는다. | 요청 전에는 전용 반영본을 제작하지 않는다. |

## 정본 문체

| 항목 | 기준 |
|---|---|
| 문체 | 건조한 백과식 정본 문체를 쓴다. |
| 구조 | 표, 짧은 정본 설명, 필요한 하위 표 순서로 쓴다. |
| 설정집 우선 | 마스터와 기준시대 정본의 본문은 항성계·행성·권역·제도·생활상의 정의와 상태 설명으로 시작한다. “어떻게 응답한다”, “무엇을 먼저 정한다”, “어떤 필드로 처리한다” 같은 운용 규칙은 본문 첫 표면이 아니라 부록·운용 문서로 내린다. |
| 금지 | 수정 이력, 구버전 비교, 작업 메모, 토론 흔적을 정본 본문에 넣지 않는다. |
| 검증 | 정본 반영 후 금칙어와 ID, 명칭, 객관정보 노출 과다 여부를 확인한다. |

## 외부 열람본 갱신 규칙

| 항목 | 기준 |
|---|---|
| 쉬운해설본 | 정본을 제3자가 읽기 쉽게 풀어 쓴 파생 열람본으로 둔다. 정보 삭제나 짧은 요약본이 아니라, 같은 정보를 더 읽히는 글로 바꾼다. |
| 갱신 시점 | 객관정보나 기준시대 객관정보의 한 단락이 정본 수준으로 확정되면 대응 쉬운해설본도 갱신한다. |
| 분리 기준 | 쉬운해설본은 정본값을 새로 만들거나 바꾸지 않는다. 정본의 정보량을 보존하되, 어려운 용어, ID, 수치, 표의 의미를 생활어와 기초 과학어로 풀어 쓴다. |
| 문체 목표 | 아주 먼 후대의 편찬자가 오래된 세계의 자연과 문명을 설명하는 글처럼 쓴다. 건조한 표를 그대로 줄이지 말고, 장중한 신화사·고대사 해설의 리듬과 읽는 재미를 붙인다. |
| 축약 금지 | 쉬운해설본을 만들 때 독자가 어렵게 느낄 만한 정보라고 해서 삭제하지 않는다. 표와 ID는 문장으로 녹여 설명하고, 필요하면 예시와 비유를 덧붙인다. |
| 직관 서술 | 쉬운해설본 맨 앞에서 “읽는 법”, “문서 사용법”, 내부 필드명, 챗봇 운용 규칙을 설명하지 않는다. 독자가 바로 세계를 볼 수 있도록 하늘, 길, 성문, 장터, 신전, 장부, 소문 같은 생활 표면에서 시작한다. |
| 내부 코드 노출 제한 | `OBJ-*`, `CK5083-*`, `speaker_scope` 같은 관리용 표식은 색인·부록이 아닌 본문 도입부에 드러내지 않는다. 필요한 정보는 “누가 말했는가”, “어디에 남았는가”, “누가 받아 주는가” 같은 생활어로 바꾼다. |
| 재미의 기준 | 농담이나 가벼운 말투가 아니라, 왜 그 자연 조건과 제도와 생활 방식이 세계를 움직이는지 독자가 따라가고 싶게 만드는 흥미를 목표로 한다. |
| 공개 기준 | 외부 공개 HTML에는 확정된 쉬운해설본만 올린다. 회차 노트, 선택지, 미확정 질문, 챗봇 전용 반영본은 올리지 않는다. |
| 동기화 기준 | 공개용 저장소는 원천 정본 저장소의 확정 산출물을 복사한 열람 표면이며, 정본 편집은 원천 저장소에서만 한다. |

## 명칭 변경 규칙

| 항목 | 기준 |
|---|---|
| 과거 통칭 보존 | 새 명칭이 생겨도 과거 통칭을 완전히 지우지 않는다. |
| 구분류 필드 | `legacy_classification`, `legacy_use_scope`, `replacement_relation`, `reader_bridge_note`로 독자 연결을 남긴다. |
| 범용 종족명 | 드워프계, 엘프계, 하플링계 같은 범용 분류명은 자칭이나 최종 정본명으로 바로 올리지 않는다. |
| 새 분류 | 철맥계, 숲기록계, 씨앗상단계처럼 기능·기억·거주 기반 분류를 먼저 만들고, 세부 자칭은 별도 단계에서 확정한다. |
| 외명과 자칭 | 공용서기어 외명, 외부 통칭, 자칭, 독자용 번역명을 별도 필드로 분리한다. |

## 언어·문자 규칙

| 항목 | 기준 |
|---|---|
| 의미 ID | 한국어 글로스는 작가용 입력 키이며 인월드 어원이 아니다. |
| 공용서기어 | 생활 공용어가 아니라 외교, 관청, 장부, 지도, 법정, 교역의 서기 접점이다. |
| 지역어 | 인간 문화권별 차이는 방언 필터와 기록 매체 차이로 먼저 처리한다. 완전 지역어는 별도 회차에서만 만든다. |
| 종족어 | 공용서기어와 같은 의미 ID를 공유하되 별도 어근망, 음운, 문자, 사용층을 둔다. |
| 난소통 이종어 | 관찰전사는 인간 기록층이다. 원음, 원문 문자, 완전 문법으로 확정하지 않는다. |
| 문자 | 현실 문자와 고대 문자는 모양, 획 밀도, 기록 매체, 음운 질감만 참고한다. 실제 낱말과 정체성은 복제하지 않는다. |

## 검증 명령

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate_arcadia.ps1
git diff --check
```

금칙어 검색은 회차별 검증 기준에 맞춰 정본 대상 파일에만 적용한다.
